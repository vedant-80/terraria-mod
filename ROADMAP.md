# NewMod Roadmap

The roadmap is stage-gated because the project identity and implementation have not yet been defined. The orchestrator should convert only approved outcomes into tasks.

## Phase 0 — Vision and constraints

- [ ] Approve pitch, player fantasy, design pillars, tone, and target audience.
- [ ] Select supported tModLoader/Terraria version and distribution target.
- [ ] Define initial scope, multiplayer support, compatibility promises, and licensing policy.
- [ ] Establish visual/audio direction with a small reference board and original test asset.

Exit: `MOD_OVERVIEW.md` has approved answers and material decisions are logged.

## Phase 1 — Technical/content vertical slice

- [ ] Initialize a buildable mod and localization structure.
- [ ] Implement one representative acquisition-to-use gameplay loop.
- [ ] Produce final-quality representative sprite, effects, text, and sound policy.
- [ ] Validate load/unload, save/reload, single-player, host/client, and dedicated server as applicable.
- [ ] Record performance and accessibility baselines.

Exit: the slice demonstrates the intended quality bar and architecture without placeholder-critical behavior.

## Phase 2 — Production

- [ ] Break approved content into dependency-aware milestones.
- [ ] Add content in reviewable vertical increments, including assets and localization.
- [ ] Maintain balance comparisons, compatibility notes, and regression checks.

Exit: planned content is complete and feature-frozen.

## Phase 3 — Stabilization and release

- [ ] Full progression, multiplayer, persistence, resolution/UI-scale, and performance passes.
- [ ] Localization, attribution/licensing, packaging, and Workshop metadata audit.
- [ ] Clean install and upgrade rehearsal with release notes and rollback plan.

Exit: no unresolved release blockers; residual risks and known issues are published.
